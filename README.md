# CrossApp

Наскрізний проєкт з крос-платформного програмування.  
Предметна область: Склад.  
Сутності: Product, StockBatch, Warehouse, Movement.  
Призначення: облік залишків товарів по партіях.

## Структура рішення

```text
CrossApp/
├── CrossApp.sln
├── README.md
├── .gitignore
├── data/
│   ├── correct_sample.csv # 10 коректних CSV-рядків
│   ├── sample.csv         # 10 коректних і 3 пошкоджені CSV-рядки
│   ├── sample.json        # 5 коректних і 3 пошкоджені JSON-елементи
│   └── sample.mixed.csv   # товари та склади в одному файлі
└── src/
    ├── Core/
    │   ├── Core.csproj
    │   ├── EnvironmentInfo.cs
    │   ├── Dto/
    │   │   ├── ProductDto.cs
    │   │   ├── WarehouseDto.cs
    │   │   ├── WarehouseEntryDto.cs
    │   │   └── ImportResult.cs
    │   ├── Import/
    │   │   ├── ProductCsvImporter.cs
    │   │   ├── ProductJsonImporter.cs
    │   │   └── MixedWarehouseCsvImporter.cs
    └── Cli/
        ├── Cli.csproj  # містить ProjectReference на Core
        └── Program.cs  # лише форматування виводу, без бізнес-логіки
```

- **`Core`** (`classlib`): центральна бібліотека логіки, яка не залежить від інтерфейсу користувача чи платформи виводу.
- **`Cli`** (`exe`): консольна точка входу, яка посилається на `Core` (`Cli` → `Core`) та відповідає виключно за введення/виведення даних.
- **`Dto`**: незмінні `record`-типи, що представляють товари, склади та результат імпорту.
- **`Import`**: логіка читання й перевірки CSV-файлу.

Каталоги `Core/Domain` і `Core/Storage` з’являться у наступних лабораторних роботах разом із доменними сутностями та сховищами.

## Збірка та запуск

### Збірка всіх проєктів рішення

```bash
dotnet build
```

### Запуск консольного застосунку

```bash
dotnet run --project src/Cli
```

Без аргументів застосунок читає `data/sample.csv`. Щоб передати інший файл:

```bash
dotnet run --project src/Cli -- data/sample.csv
```

### Збірка окремо бібліотеки Core

```bash
dotnet build src/Core/Core.csproj
```

## Публікація

### 1. Framework-dependent (потребує встановленого .NET 10 Runtime)

```bash
dotnet publish src/Cli -c Release -r win-x64 --self-contained false -o publish/win-x64-fd
```

### 2. Self-contained (включає .NET Runtime у вихідний каталог)

```bash
dotnet publish src/Cli -c Release -r win-x64 --self-contained true -o publish/win-x64-sc
```

### Запуск опублікованого застосунку

```powershell
# Приклад для Windows:
.\publish\self-contained\Cli.exe
```

---

## Порівняння режимів публікації

| RID         | Режим               | Розмір publish | Потрібен встановлений runtime |
| :---------- | :------------------ | :------------- | :---------------------------- |
| `win-x64`   | self-contained      | ~76.67 МБ      | Ні                            |
| `win-x64`   | framework-dependent | ~0.19 МБ       | Так (.NET 10)                 |
| `linux-x64` | self-contained      | ~78.80 МБ      | Ні                            |

### Різниця режимів

- **Framework-dependent** містить лише скомпільований код застосунку та залежності, тому має мінімальний розмір. Працює лише на машинах із попередньо встановленим сумісним середовищем .NET Runtime.
- **Self-contained** пакує застосунок разом із копією середовища виконання .NET Runtime для цільової платформи (RID). Не вимагає наявності встановленого .NET на машині клієнта, але має значно більший розмір і прив'язаний до конкретної ОС/архітектури.

## Додаткові завдання (Лабораторна 1)

### 1. Порівняння розмірів Self-contained збірок

- `linux-x64` publish: **70.51 MB** (70.513 MB)

### 2. Запуск з прапорцем --json (лабораторна 1)

Цей режим був реалізований у версії лабораторної 1. У поточній версії аргумент командного рядка використовується як шлях до CSV-файлу.

## Додаткові завдання (Лабораторна 2)

### 1. Додаткові режими публікації

Для цільової платформи `win-x64` було протестовано розширені прапорці компілятора:

| Режим / Прапорці                                   | Опис                                                        | Розмір       | Кількість файлів   |
| :------------------------------------------------- | :---------------------------------------------------------- | :----------- | :----------------- |
| `-p:PublishSingleFile=true`                        | Пакування рантайму, бібліотек та застосунку в один бінарник | ~70.12 МБ    | 1 файл (`Cli.exe`) |
| `-p:PublishSingleFile=true -p:PublishTrimmed=true` | Вирізання невикористаного коду рантайму (Assembly Trimming) | **12.35 МБ** | 1 файл (`Cli.exe`) |

> **Пояснення Trimming**: Прапорець `PublishTrimmed` дозволив зменшити бінарник майже в 6 разів (з 70.5 МБ до 12.35 МБ). Попереджень компілятора не виникло, оскільки код застосунку та бібліотеки `Core` не використовує динамічну рефлексію. Trimming потенційно небезпечний для коду з reflection або динамічною JSON-десеріалізацією, оскільки компілятор може видалити типи, які викликаються лише за назвою в рантаймі.

### 2. Multi-targeting бібліотеки Core

У проєкті `src/Core/Core.csproj` налаштовано збірку під дві цільові платформи:

```xml
<TargetFrameworks>net8.0;net10.0</TargetFrameworks>
```

У коді `EnvironmentInfo.cs` застосовано директиву умовної компіляції (`#if NET10_0_OR_GREATER`), що додає поле `BuildNote`. При виконанні `dotnet build src/Core/Core.csproj` успішно створюються два окремі артефакти в каталогах `bin/Debug/net8.0/Core.dll` та `bin/Debug/net10.0/Core.dll`.

## Лабораторна 3: імпорт складських даних

Для представлення даних створено `ProductDto`, `WarehouseDto` та узагальнений тип `ImportResult<T>`. Клас `ProductCsvImporter` читає CSV, повертає коректні товари та окремо збирає помилки пошкоджених рядків.

### Формат CSV

- кодування: UTF-8;
- роздільник: `;`;
- заголовок необов’язковий;
- колонки: `id;sku;name;unit;quantity`.

Приклад:

```csv
id;sku;name;unit;quantity
P-001;SKU-001;Цемент М400 25кг;шт;120
P-002;SKU-002;Пісок будівельний;т;18
```

Порожні рядки та коментарі, що починаються з `#`, пропускаються. Рядки з неправильною кількістю колонок, порожніми обов’язковими полями, нечисловою або від’ємною кількістю не переривають імпорт, а додаються до переліку помилок з номерами рядків.

### Приклад виводу

```text
Завантажено записів: 10
...
Пропущено рядків: 3
  ! рядок 12: очікую 5 колонок, отримав 4
  ! рядок 13: кількість 'багато' не є невід'ємним цілим числом
  ! рядок 14: ідентифікатор, SKU, назва або одиниця вимірювання порожні
```

### Додаткове завдання 1: імпорт JSON

Для тих самих `ProductDto` реалізовано `ProductJsonImporter` на основі `System.Text.Json`. Консольний застосунок обирає імпортер за розширенням файлу:

```bash
dotnet run --project src/Cli -- data/sample.csv
dotnet run --project src/Cli -- data/sample.json
```

Назви JSON-властивостей зіставляються без урахування регістру. Елементи масиву обробляються окремо: записи з порожніми обов’язковими полями, від’ємною кількістю або невідповідними типами потрапляють до `Errors`, а інші залишаються в `Items`. Синтаксично зламаний JSON повертається як помилка всього документа.

### Додаткове завдання 2: різнорідні рядки CSV

Файли з суфіксом `.mixed.csv` можуть містити товари та склади. Префікс рядка визначає тип запису:

```text
P;id;sku;name;unit;quantity
W;id;name;location
```

Запуск:

```bash
dotnet run --project src/Cli -- data/sample.mixed.csv
```

`MixedWarehouseCsvImporter` використовує один `switch expression` з list patterns для розпізнавання обох форматів. Правильні рядки повертають `ProductDto` або `WarehouseDto` через спільний базовий тип `WarehouseEntryDto`.

### Додаткове завдання 3: статистика імпорту

Після імпорту CSV, JSON або змішаного CSV застосунок виводить загальну кількість оброблених записів, кількість прийнятих і пропущених та відсоток помилок. Заголовки, порожні рядки та коментарі не враховуються.

```text
Статистика: усього 13, прийнято 10, пропущено 3, помилок 23,1%
```
